# 리눅스 커널 소스 참조 (linux-page-walk)

그림의 규칙이 리눅스 7.0.14의 어느 줄에서 나오는지 가리키는 목록이다. 커널 소스(GPLv2)는 이 저장소(MIT)에 옮기지 않는다. 코드 원문 대신 고정 태그의 줄 범위 링크, 함수명, 그 줄이 하는 일을 우리 말로 쓴 요약만 적는다.

- 저장소: linux stable (`git.kernel.org/pub/scm/linux/kernel/git/stable/linux.git`)
- 태그: `v7.0.14` (태그 객체 `b38d6c0b6e7f406a7feb7d46f184ec3edaac8c3b`, 커밋 `458c6079fc1d41d564c37679c8ace02cd83ee817`)
- 실행한 빌드: Docker Desktop의 `7.0.14-linuxkit #1 SMP PREEMPT`, arm64. linuxkit 빌드가 패치를 몇 개 더 얹었을 수 있다. 줄 참조는 upstream 태그이고, 측정값(`truth/*.txt`)은 linuxkit 빌드에서 나왔다
- 원문 확인: `bash truth/fetch-kernel.sh`로 아래 파일을 임시 폴더에 받은 뒤 `node check-source.mjs`. 받은 파일의 SHA-256은 `fetch-kernel.sh`에 고정해 두었고, `check-source.mjs`는 표의 "대조 식별자"가 각 줄 범위 안에 있는지와 모델이 기대는 줄들을 확인한다

## 이 그림에서 하드웨어가 하는 일과 커널이 하는 일

- 주소 변환(TLB 조회, 4단 테이블 걷기)은 CPU의 MMU가 한다. 커널 코드는 걷기에 끼어들지 않는다. 커널은 테이블을 만들어 두고(L0 테이블의 물리 주소를 `TTBR0_EL1`에 넣는 `cpu_do_switch_mm`), 걷기가 실패해 예외가 나면 그때 들어와서 빈 칸을 채운다
- 걷기가 몇 번째 단계에서 멈췄는지는 MMU가 ESR의 DFSC로 알린다(`fault_info` 표의 "level N translation fault"). 이 VM에서는 `do_mem_abort`가 kprobe 금지(`NOKPROBE_SYMBOL`)라 ESR 값을 직접 읽지 못했다. 단계는 아래 표의 커널 분기와 ftrace에 찍힌 할당 함수로 정했다: `__pte_alloc`이 불렸으면 L2 항목이 비어 있었고, `__pmd_alloc`과 `__pud_alloc`이 불리지 않았으니 L0, L1 항목은 있었다

- TLB가 실제로 맞았는지 빗나갔는지: 이 VM에는 하드웨어 PMU가 없어 `dTLB-load-misses` 같은 이벤트를 쓸 수 없다. 그림의 카드 인덱스는 Arm 아키텍처가 정한 동작(빈 항목이나 fault를 낸 항목은 TLB에 두지 않는다. 걷기에 성공한 결과는 둘 수 있다. 무효화하면 지운다)만 그리고, 성공한 결과는 늘 남아 있다고 가정한다
